# FigFox-Gen V2: Evidence-Grounded Scientific Figure Generation

## Inputs and scope
The workflow converts a scientific Methodology and optional user reference images into one source-grounded raster figure, PNG1. The Methodology supplies all scientific components, assumptions, directed relationships and contribution claims. References supply scoped drawing conventions, not another study's scientific content. The current workflow runs through the calling Harness and available tools rather than a separate model service. It ends at image delivery and inspection; editable reconstruction is outside this generation workflow.

## Visual-needs anchoring
The executor reads the Methodology and inspects approximately two comparable scholarly figures. One synthesis retains visual conventions only when the current Methodology needs them. It records the scientific input/output types, useful intermediate artifacts, meaningful topology and comparisons, and the finest contribution-level detail actually shown by the peers. Stable visual-need IDs link this anchor to later drawing decisions. The peer examples inform how far to expand a contribution, whereas the current Methodology determines what that contribution is. Unchanged supporting models stay at a consistent, coarser level.

## Parallel preparation and scientific graph
After the anchor, independent preparations run concurrently. One branch considers useful existing assets and distinguishes direct scientific content, source crops and construction/style evidence. Direct-use assets retain their actual pixels and require recorded sources and permission. A second branch inspects drawing constructions for the selected needs, using recognizable canonical grammar only for models actually named by the Methodology. A third branch establishes a coherent main visual language and scoped detail traits, including typography, frames, spacing and arrow proportions, and matches a compatible approved palette. Palette selection can overlap other work once the intended traits are clear. Without an approved main reference, the Creative Director composes a coherent style from the brief. Source-checked caches are reused, and further retrieval is limited to a named unresolved need. The scientific component/edge graph is preserved independently of the stylistic evidence.

## Drawing correspondence and creative construction
The preparations join in a need-to-drawing correspondence: every selected need specifies where it appears, the inspected construction borrowed, and how the current scientific content is drawn. Direct-content assets are distinct from stylistic references. The Creative Director performs one ideation pass over this correspondence and the scientific graph. It first fixes the complete rectangular footprint, regular peer regions and dominant reading direction, then designs concrete artifacts and local constructions. Reverse-C, S-shaped, circular and parallel arrangements are options governed by the actual scientific graph, not mandatory topologies. Ports and routes are planned with the module placements. Neighboring regions use related pale colors; a separated accent highlights the key mechanism. White space, black readable text and restrained fills dominate. The Director assigns innovation-led detail, inventories exact visible text and symbols, removes repeated prose and nonsemantic decoration, and normally targets about 100 English words or fewer, with a default absolute ceiling of 160 unless the user explicitly supplies a different budget. Necessary notes remain readable, and notation uses approved typeset aliases rather than visible underscores.

## Deterministic preflight and compact handoff
The V2 generation plan records a bounded canvas, row/column tracks, one grid slot per component, and explicit orthogonal paths with source/target ports. Every scientific edge must appear exactly once. Both prompt builders check geometry, need coverage and notation. Detached endpoints, blocked paths, ambiguous shared target landings, undeclared crossings and unnecessary detours require plan revision before generation. These corrections revise the plan and recompile it; they are not extra image-generation calls. The compact packet contains scientific invariants, components and connections, concrete local constructions, scoped reference contracts, selected palette, the Director's decisions and approved text/symbol inventories. Full research, rejected candidates and repeated source prose stay in provenance records. Fingerprints support deterministic replay, not proof of truth.

## Single generation, optional asset placement and inspection
The checked packet and its approved attachments drive one image-generation call. If direct-content assets were selected, the generated layout reserves their declared slots and a deterministic compositor places the actual inspected files without another model call; otherwise the generated image is PNG1 directly. This optional path is a pass-through when no assets are selected. The executor then checks file/provenance consistency and visually inspects the actual image for scientific topology, labels, text economy, continuous arrows, alignment, readable typography and asset fidelity. These checks remain separate: a valid file and plan do not certify correct pixels. The first result, exact prompt, evidence and timings are retained, and defects are reported rather than silently replaced. A further image or repair requires an explicit separate request.
