# SVG-reference workflow contract

Active new runs use style-brief `workflow_policy: "svg-reference-v1"`, Context1 `reference_policy: "svg-only"`, Context3 `reference_strategy: "essential-only"`, and palette `source_mode: "svg-reference"`. Legacy fixed-library artifacts are for archival replay only.

A palette contains the existing base_palette_id (now a source identifier), dominant_colour_roles, colours and extensions, plus reference and relationships. Reference records path to a retained complete SVG, SHA256, HTTPS source_url/evidence_url, source_track, target_track, complete_figure:true. Source and task tracks must differ. Base colours must actually occur as paints in the SVG; external CSS may be embedded without altering its paint values, with original SVG/CSS retained. No embedded raster. Local PNG previews may only be rendered from the verified SVG for viewing or model transport.

Each relationship names two source colour roles, relation adjacent/separate and a concrete source observation. Each derived extension records role, HEX/RGB, base_role, relationship (tint/shade/tone/analogous_neighbour/compatible_neutral/controlled_contrast), evidence_url and evidence_summary. Keep colour roles unique. Changing the source hash or user palette requires a fresh Director review.

Director brief keeps format creative-director-brief-v1 and original ideas. It adds design_intents, topology_review and colour_decision. The latter has chosen_palette, rationale, region_colours (every component mapped to colour-role lists or white/black), adjacency_review and whitespace_plan. It preserves source/observations while deciding actual use and derivatives. Inventory all visible strings and symbols. New runs without this decision cannot compile PNG1.

The Director receives science and complete reference traits before final geometry exists. It writes V2 generation-plan after deciding colour and composition. Routing geometry uses routing_policy simple; existing canvas/tracks/slots plus optional multi_port_exceptions keyed by component ID with a scientifically supported reason. Straight routes have points:[start,end]. A quadratic/cubic route has curve:"quadratic" or "cubic" and respectively 3/4 Bezier control points, plus the usual exact source/target ports and route_kind. Do not interpret control handles as polylines. No staircase. Move frames before routing; prefer one input/output per frame. Curve checks sample the path and reject gross obstruction, not guarantee exact rendered pixels.

Web manifest source crop_path points to genuine retained SVG, not retrieved PNG. Main/style SVGs may be rendered locally for model transport with original source path and hash retained. Use only permitted model-reference attachments; source SVG membership is not blanket publication permission.

New run-manifest format is figfox-svg-run-v1. Its exact artifacts map contains methodology, context1, context2, context3, web_manifest, creative_director_prompt, creative_director_brief, prompt1, prompt1_attachments and png1, using canonical paths from run_artifact_paths(). No unused legacy FigureBench artifacts are required. validate-run verifies source SVGs/palette, Director decision, simple geometry, deterministic prompt/attachments and the one PNG; pixel inspection is still mandatory.
