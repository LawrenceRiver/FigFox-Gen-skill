# Compact generation handoff (`codex/style-anchor-fast`)

Use this route for style-first tasks. Complete the same evidence artifacts, then write `input/generation-plan.json` after Context2 is resolved. Both Creative Director and Prompt1 consume one checked generation checklist instead of raw Context JSON and search notes. No plan means legacy/style-anchor compilation remains available. This branch does not reinstall the production skill or merge main.

## Circuit and retrieval stop conditions

1. Read Methodology and inspect about two same-category peer figures. In one response, ground common input/output, topology, intermediate-view and comparison needs in the actual Methodology. Record peer finest/shared detail levels and the real innovation focuses. This is the stable needs anchor, not a long paper-summary stage.
2. From that list, concurrently find useful icon/illustration constructions, extract explicitly liked main-reference traits, and match the approved palette. Do not retrieve an image per component. C/reverse-C and ordinary arrow routing are creative-layout knowledge, not another search task.
3. Each branch returns selected source/crop IDs, observed construction and unresolved need IDs. Reuse valid inspected sources/crops; stop at effective coverage. Archive rejected candidates/search transcripts instead of forwarding them. FigureBench and FigFoxBench are distinct sources.
4. Join into one need-to-drawing correspondence table. Creative Director and palette work settle a coherent system; native ordinary geometry needs no additional survey once its observed treatment is settled. Plan placement, hierarchy and continuous arrow paths together, then lock the packet.
5. Compile and generate one PNG1 for this run. Validate replay/provenance, then inspect actual pixels. A requested new comparison or explicit connector edit is recorded separately, retaining the previous image. No automatic review/search/repair loop.

Log actual cache hits, batch starts/ends, joins and model stage times. Cached reruns are not evidence of a measured cold-search speedup. The skill schedules the calling Harness; it does not ship a network crawler or promise tool concurrency where dependencies require a join.

## Generation plan

The complete JSON has these fields (replace the two-component example with the actual complete Context2 graph):

```json
{
  "format": "figfox-generation-plan-v1",
  "scientific_summary": "Input is encoded into Output under fixed model parameters.",
  "invariants": ["Model parameters remain fixed."],
  "layout": "Landscape; Input left, Output right, with room for labels.",
  "typography": "Arial, consistent dark text; necessary short notes Arial Italic.",
  "placements": [
    {"component_id": "input", "placement": "left"},
    {"component_id": "output", "placement": "right"}
  ],
  "routes": [
    {"source_id": "input", "target_id": "output", "label": "encodes",
     "source_port": "east", "target_port": "west", "via": "direct arrow"}
  ],
  "local_visuals": [
    {"target_component_id": "input", "meaning": "source document",
     "construction": "Native folded-page outline with PDF text, no branded logo.",
     "basis": "Rectangle, polygon, lettering; document input in Methodology."}
  ]
}
```

Exactly one placement per actual component; every Context2 relationship is routed once with the same endpoints and scientific label. No invented edge or silent omission. Ports must name the actual node/container border. Evidence edges into a planner must have independent arrowheads; outer return ends at the actual harness, not a nearby input. Repeated thumbnails are insets, not duplicated pipeline nodes. A container can represent a component directly. The validator checks the declared graph and cannot verify drawn arrowheads.

The Harness writes `scientific_summary` and `invariants` from the Methodology and checks them against source excerpts before compilation. Keep assumptions, acceptance inequalities, fixed/trainable status, data isolation and named choices explicit; do not discard these as retrieval detail. The compiler preserves all exact component labels, treatments and relationships; it cannot detect a misleading human/model-authored summary.

For each useful miniature, name its target, scientific meaning, construction and basis. Examples: PDF page glyph for document input; tiny before/after schematic artifact snapshots for iterative refinement; ordered event marks for execution traces; rubric cells for fixed evaluation; a ruled log for persistent memory. Use real targeted construction crops when needed; after an observed construction is selected, native editor primitives need no further paper search. Do not skip actual reference inspection merely because a generic icon can be drawn easily. Keep microviews readable and coherent with the main style. Do not turn schematic snapshots into fabricated results or add arbitrary particles. `local_visuals` may be empty when the science has no useful inset.

## What the image model receives

- Concise scientific meaning and invariants, one overall framework description.
- One component/placement/treatment listing and one source-port → target-port route listing.
- Semantic miniatures and explicit typography specification.
- One global style reference, then scoped local references with actual pixel dimensions/aspect context and their borrow/change contracts. Keep labels, frames, arrows and font treatment coherent.
- The approved palette, final creative construction choices and concise drawing checks.

Full Methodology, research summaries, discarded candidates, provenance rationale and repeated coverage explanations stay in run artifacts. A SHA256 fingerprint binds them to the compiled prompt for deterministic replay; it does not certify scientific truth. Prompt1 stops above 24,000 characters with a clear error instead of silently truncating science or submitting an oversized request. Shorten redundant planning prose if necessary.

## Creative Director: route before freezing placement

Arrows should be easy for a person to reproduce in an editor. Plan object placement and connection clearance together: prefer a straight mainline, move modules to remove avoidable intersections, and only then lock ports/routes. Keep short local branches; use a consistent few right-angle bends or one purposeful feedback arc when necessary. A long perimeter return is appropriate for an actual outer loop. Do not accept a maze of detours just because coordinates were chosen early. Revise the plan and recompile the Director prompt before generation if the proposed placement forces such a maze.

Every shaft is continuous from its real source border to its target arrowhead. No empty-space starts, isolated arrowheads, suddenly disappearing lines or broken segments hidden behind text. Put relation labels beside the line. Avoid crossings; an unavoidable crossing uses a visibly continuous bridge, never an unexplained erased gap or an ambiguous junction. Inspect each source-to-target route against these rules, not merely the presence of endpoint names in the JSON. These requirements are sent to both Creative Director and generator.


## Select references for generation, retain research locally

An optional `attached_reference_paths` list in the generation plan selects the model-visible images from the already validated attachment candidates. Keep the approved global/detail style references and any required new Creative Director construction evidence; unselected secondary FigureBench/domain geometry evidence stays in the audit artifacts. Unknown paths, duplicate paths, or dropping an approved style reference are errors. Without this list all mapped attachments remain attached. Selection is deliberate, not automatic image-count truncation. For a user-requested two-reference design, prefer a coherent global/font reference plus a construction reference whose actual pixels answer the difficult visual concept.

Use the source list in [redesign-reference-pair.json](redesign-reference-pair.json) as inspected leads, not a universal template. Recheck visual fit for the current Methodology. NoWait and Paper2Poster are this trial's complementary pair; own content replaces original tokens, paper screenshots, logos and mascots. Preserve meaningful visual miniatures rather than filling every method node with a generic icon. The image model receives only selected images and compact contracts; full paper/source inspection remains local.

## The anchor and detail hierarchy (current route)

Do one peer/Methodology synthesis before borrowing: about two actually inspected same-category figures, with source-specific observations of input/output, topology/intermediates, comparisons, and their finest/shared detail levels. Retain a visual need only when the Methodology needs that convention. Context1 records this once; copy its concise selected entries into `visual_needs` rather than asking for another summary. Then icons/illustrations, liked main-reference traits, and palette matching can proceed independently. Ordinary C/reverse-C routing is creative-layout knowledge, not an extra retrieval stage. New checklist runs accept two inspected scholarly sources; legacy runs keep their original minimum.

```json
{
  "visual_needs": [
    {"id":"v-input", "need":"source document view",
     "methodology_evidence":"The method consumes a PDF document.",
     "peer_evidence":"Inspected source A Fig1 and source B Fig2 show real input-page anatomy."}
  ],
  "local_visuals": [
    {"need_id":"v-input", "target_component_id":"input", "meaning":"paper input",
     "basis":"Observed staggered-page construction in source A Fig1",
     "construction":"Draw our own paper-page anatomy with its real input type."}
  ],
  "detail_hierarchy": {
    "peer_depth_observation":"A expands its novel local operation; B keeps the unchanged model whole.",
    "innovation_focuses":[{"claim":"Source-supported new mechanism", "component_ids":["output"],
                           "draw_to":"The actual operation and its visible intermediate/result"}],
    "common_depth":"All supporting stages remain at input/whole-model/output level.",
    "keep_whole":["input"]
  }
}
```

Defined visual-need IDs must each have a drawing correspondence; unknown or uncovered IDs fail compilation. This is coverage of needed visual concepts, not an image-search obligation per component. The generated packet contains one compact correspondence table. `detail_hierarchy` sends innovation focus, finest visible unit and common supporting depth to both Creative Director and image model; known component IDs are checked. Older archived plans without these fields remain readable.

Use a fast contribution test: (1) what new mechanism does the source actually claim? (2) what is the finest visible unit in the inspected peers? (3) at that unit, what must be drawn to explain our contribution? (4) which supporting parts should stay at a common coarser level? Usually one or two contribution themes, but do not manufacture or suppress claims to hit a count. A familiar model is a whole block unless model internals are the innovation. At the same supporting level, avoid arbitrary uneven expansion. Scientific relationships remain complete even when internal detail is collapsed. The compiler validates IDs and coverage, not whether an innovation claim is true; verify claims against Methodology.
